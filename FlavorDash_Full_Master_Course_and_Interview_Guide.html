🌐 CHAPTER 1: Fundamental Concepts & Internet Basics

1.1 What is Web Development?

Web development is divided into two primary sides:

  • Frontend (Client Side): What the user sees on their browser screen (buttons, forms, food images, colors). Built using HTML (structure), CSS (styling), and JavaScript/React (interactivity).
  • Backend (Server Side): The unseen logic running on computers around the world. It processes user requests, verifies passwords, calculates shopping cart totals, processes payments, and reads/writes to databases. Built using Java / Spring Boot.

1.2 How Does the Internet Work?

When you type http://localhost:3000 or https://flavordash.com in your browser:

  1. Browser (Client) sends an HTTP Request to the Server.
  2. Server processes the request and queries the Database.
  3. Server returns an HTTP Response containing JSON Data.
  4. Frontend receives the JSON data and updates the user interface on screen.

1.3 What is JSON (JavaScript Object Notation)?

JSON is a lightweight text format used by servers and browsers to talk to each other. Here is what a product JSON looks like in FlavorDash:

{
  "id": 1,
  "name": "Butter Chicken Special",
  "price": 380,
  "category": "Main Course",
  "isVeg": false,
  "calories": 450,
  "protein": "32g"
}

1.4 Monolithic vs Microservices Architecture

Feature Monolithic Architecture Microservices Architecture (FlavorDash)
Structure All features in 1 single massive codebase. Split into 7 smaller, independent applications.
Scalability Must scale the entire app together. Scale only heavy services (e.g. Product Service) independently.
Fault Isolation If 1 feature crashes, the whole app dies. If Payment fails, users can still browse menus safely.
Deployment Re-deploying requires stopping everything. Deploy services independently without downtime.

3.1 Important Spring Boot Annotations to Know

  • @SpringBootApplication: Marks the starting point of a Spring Boot application.
  • @RestController: Tells Spring that this Java class handles REST API requests and returns JSON.
  • @GetMapping("/api/products"): Listens for HTTP GET requests at that URL.
  • @PostMapping("/api/users/register"): Listens for HTTP POST requests to create new data.
  • @Entity: Maps a Java class directly to a database table.
  • @Autowired: Automatically injects helper service classes into controllers (Dependency Injection).

3.2 Apache Kafka Event-Driven Architecture

Instead of synchronous waiting, microservices publish real-time events to Kafka:

Order Placed ➔ Order Service publishes "ORDER_CREATED" event to Kafka ➔ Payment Service consumes event & processes payment ➔ Payment Service publishes "PAYMENT_SUCCESS" event

⚛️ CHAPTER 4: Frontend React 18 & Vite Architecture

4.1 Key React Concepts Used

  • JSX: HTML written inside JavaScript code (e.g. <div className="food-card">).
  • useState Hook: Holds dynamic data (like cart item count or active menu filter).
  • useEffect Hook: Triggers actions when page loads (e.g. fetching food items from API).
  • useContext Hook: Shares global state (user login state, cart contents) across all components without prop drilling.
  • React Router: Handles page navigation without refreshing the browser (`/`, `/menu`, `/orders`, `/kitchen`, `/driver`).

🚀 CHAPTER 5: God-Mode Features & Business Logic

1. Swiggy/Zomato-Style Floating Cart Strip

When items are added to the cart, a sleek glassmorphic bottom bar slides up showing total item count, total price, and a 1-tap "Checkout" button accessible from any page.

2. 🟢 Veg / 🔴 Non-Veg Badging & AI Dietary Filters

Adheres strictly to Indian FSSAI food badging guidelines with green square/dot for Vegetarian and red square/dot for Non-Vegetarian. Users can filter dishes by High Protein 💪, Keto 🥑, Jain Friendly 🌿, or Low Calorie ⚡.

3. 👥 Group Ordering & Instant UPI Bill Splitting

Users click "Group Order" in the cart to generate a unique room code (e.g. FLAVOR-4892). Friends join the room, add items, and the modal automatically calculates per-person bill breakdowns with instant UPI QR payment links.

4. 🔒 Role-Based Access Control (``)

Role access is strictly tied to logged-in user profile (CUSTOMER, HOTEL_MANAGER, RIDER):

  • Customer: Access to Home, Menu, Cart, Orders.
  • Hotel Manager: Unlocks /kitchen (Merchant Kitchen Order Pipeline & Stock Controls).
  • Rider Agent: Unlocks /driver (Delivery Rider GPS Telemetry Stream).

If an unauthorized role visits a protected route, `` blocks access and redirects to Home with an error toast alert.

🎓 CHAPTER 8: Ultimate Technical Interview Master Kit (50+ Q&A)

Q1: "Can you summarize your project in 30 seconds?"
"FlavorDash is a full-stack food delivery application built using Spring Boot 3 microservices and a React 18 frontend. It features 7 decoupled microservices—including API Gateway, Eureka Discovery, User, Product, Order, and Payment services—communicating asynchronously via Apache Kafka. Frontend innovations include collaborative group bill splitting, AI nutrient filtering, a merchant kitchen desk, and rider GPS telemetry tracking."
Q2: "Why did you choose Microservices over a Monolith?"
"In food delivery systems, different features experience vastly different traffic patterns. Product searches occur millions of times a day, whereas Payments happen only during checkout. Microservices allow us to scale Product Service independently without duplicating Payment Service, ensure fault isolation if one service experiences issues, and enable independent deployments."
Q3: "How do your Microservices talk to each other?"
"We use two modes: 1) Synchronous REST via Spring Cloud OpenFeign for real-time queries (e.g. Order Service fetching Product pricing during checkout), and 2) Asynchronous event-driven messaging via Apache Kafka for broadcasting order and payment events."
Q4: "What is the function of the Eureka Discovery Server?"
"Eureka Server running on port 8761 acts as a live directory. When microservices start up, they register their IP address and port number. When API Gateway needs to forward a request, it looks up the service location dynamically from Eureka instead of hardcoding hostnames."
Q5: "How does your frontend handle authentication and role security?"
"User profiles store roles (`CUSTOMER`, `HOTEL_MANAGER`, `RIDER`). React Context (`AuthContext`) manages login state. Protected pages like `/kitchen` and `/driver` are wrapped inside a `` component that verifies user role permissions before rendering the page."
Q6: "How did you deploy the application?"
"The React frontend is deployed on Vercel with single-page app routing rewrites (`vercel.json`). The Spring Boot microservices are containerized using multi-stage Dockerfiles and deployed on Render.com."
