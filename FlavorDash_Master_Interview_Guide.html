FlavorDash — Master Project & Technical Interview Guide

Full-Stack Microservices Food Delivery Platform (Spring Boot 3 + React 18)

📚 MODULE 1: PROJECT OVERVIEW & EXECUTIVE SUMMARY

FlavorDash is a modern enterprise food delivery web application built using a Spring Boot 3 Microservices Architecture on the backend and a React 18 + Vite frontend.

It mirrors real-world platforms like Swiggy, Zomato, and DoorDash with key innovations:

  • 🛒 Swiggy/Zomato-Style Floating Cart Strip: Bottom bar with instant 1-tap checkout across all pages.
  • 👥 Multi-User Group Ordering & Instant UPI Bill Splitting: Room code sharing & automatic bill splitting.
  • 🧠 AI Macro-Nutrient & Dietary Engine: Filter by High Protein 💪, Keto 🥑, Jain 🌿, and Low Calorie ⚡.
  • 👨‍🍳 Merchant Kitchen Dashboard (/kitchen): Live order status management for restaurant chefs.
  • 🛵 Rider Telemetry & GPS Tracker (/driver): Interactive delivery partner dashboard with route simulation.
  • ⚙️ Live Backend Diagnostics Modal: Real-time health monitoring of all 7 microservices.

🎓 MODULE 4: TOP INTERVIEW QUESTIONS & ANSWERS (0 to 100)

Q1: "Walk me through your project in 30 seconds."

Answer: "FlavorDash is a full-stack food delivery platform built with Spring Boot 3 microservices and React 18. It includes 7 microservices—API Gateway, Eureka Registry, User, Product, Order, and Payment services—communicating via REST and Apache Kafka. Frontend highlights include multi-user group bill splitting, AI diet filters, a kitchen portal, and rider GPS tracking."

Q2: "Why did you use Microservices instead of Monolith?"

Answer: "Different services experience different loads. Product searches happen millions of times a day, whereas Payments occur only at checkout. Microservices allow independent scaling, fault isolation (if payment fails, users can still browse menus), and independent team deployments."

Q3: "How do your Microservices communicate?"

Answer: "We use both: 1) Synchronous REST with Spring Cloud OpenFeign for immediate queries (e.g. fetching product details), and 2) Asynchronous event-driven messaging with Apache Kafka for order status updates."

Q4: "How did you implement Role-Based Access Control?"

Answer: "User profiles contain roles (CUSTOMER, HOTEL_MANAGER, RIDER). On React, a <ProtectedRoute> guard inspects the logged-in role and blocks unauthorized access to /kitchen or /driver."

Q5: "How does Group Bill Splitting work?"

Answer: "Users generate a room code (e.g. FLAVOR-4892), invite friends to a shared cart, and the app dynamically calculates individual shares and generates instant UPI payment QR requests."
